# DDNS IPv4 来源选择增强版

基于 [fxxkmkd/cf-ddns](https://github.com/fxxkmkd/cf-ddns) 修改，保留原脚本的 Cloudflare、华为云 DDNS 及后台运行功能，新增 **IPv4 来源对比、手动选择和持久化**。

适合普通 IP 查询结果与网卡直连检测结果不一致的 NAT VPS、代理或网络分流环境。

## 为什么需要这个版本？

部分服务器通过普通 IP 查询接口获取的地址，可能是代理或其他出口的 IP，并非希望用于 DDNS 的地址。

本版本提供两种 IPv4 获取方式：

| 获取方式 | 说明 |
| --- | --- |
| 普通查询 | 沿用原脚本的多个公网 IP 查询接口 |
| 网卡直连 | 通过 `eth0` 请求 `https://1.1.1.1/cdn-cgi/trace`，提取 `ip=` 字段 |

直连检测使用：

```bash
curl -q -fsS -4 \
  --interface eth0 \
  --noproxy '*' \
  --max-time 10 \
  https://1.1.1.1/cdn-cgi/trace
```

其中，`--noproxy '*'` 用于绕过 curl 代理，`-q` 用于忽略默认 curl 配置文件，减少配置干扰。

## 工作逻辑

尚未选择来源时：

- 两种方式获取的 IPv4 相同：直接使用该地址更新。
- 两种方式获取的 IPv4 不同：交互运行时显示结果，让用户选择。
- 只有一种方式检测成功：让用户确认是否使用该来源。
- 两种方式均失败：保留原 DNS 记录。
- 后台运行时需要用户选择：跳过本次更新并记录日志，等待用户从菜单完成选择。

**一旦用户选择，脚本会记住所选 IP 对应的获取方式。**

例如，选择了“eth0 直连”，以后就始终通过该方式获取最新 IPv4 并更新 DDNS。保存的是获取方式，而不是固定的 IP 数值。

所选来源检测失败时，脚本会保留原 DNS 记录，不会自动切换到另一个来源。

## 使用方法

下载本仓库中的 `cf-ddns.sh`，在服务器上运行：

```bash
bash cf-ddns.sh
```

首次使用可通过菜单完成 DDNS 配置，然后执行一次同步。

新增菜单：

```text
8. 选择 / 更换 IPv4 获取方式（持久化）
```

可以随时通过菜单 **8** 重新检测两路 IPv4，并更换后续 DDNS 使用的来源。

### 从原版升级

使用与原版相同的用户运行新版脚本，以便沿用原有配置。

如果已经开启后台任务，请运行新版后选择菜单 **4：开启 / 修改后台定时任务**，重新启动后台任务，使新版逻辑生效。

## 持久化

来源选择保存在当前配置目录中的：

```text
ipv4-source.conf
```

默认位置：

```text
~/.cf_ddns/ipv4-source.conf
```

文件内容为：

```text
normal
```

或：

```text
direct
```

分别表示普通查询和网卡直连。

该文件独立于域名及 API 配置保存，重新配置 DDNS、重启脚本或重启服务器后，仍会沿用已选来源。

## 注意事项

- 直连网卡默认为 `eth0`。如果实际网卡名称不同，请修改脚本 `get_direct_ipv4()` 函数中的 `local interface="eth0"`，并重新启动后台任务。
- `--noproxy` 的参数应写成 `'*'`，不要写成 `'\*'`。
- 本次修改针对 IPv4，IPv6 保留原脚本的检测逻辑。
- 直连检测得到的是该请求实际使用的公网出口地址。NAT 的入站地址、端口映射仍需以服务商提供的信息为准。
- DDNS 负责更新 DNS 记录，不会自动配置 NAT 端口映射或防火墙。
